## M3 Goal (Architecture Spec §A)

> **Multi-bar placement on a face with spacing, cover, and edge distance** — the §F.2 Individual mode (fire-and-forget stays exactly as M0 shipped it) and the Group mode (rule-based region placement: the group stores the placement rule; param edits re-generate the bars; moving an individual bar breaks it from the group).
> **Risks probed:** face-sampling algorithm · collision detection · placement UX (group-region definition on a face).

**Milestone acceptance:**

1. **Group placement, rule-exact (headless):** a wall built through the §N commands → `placeBarGroup` (target face, region, Ø, cover, spacing, edgeDistanceStart/End, orientation) → the generated bars satisfy the stored rule **exactly** — bar count derived from region/spacing/edges, centerline positions exact, every bar keeps its cover from ALL element faces (the M0 `applyConcreteCover` clamp semantics — edges/start/end included), `hostElementId` set on every bar, one shared `barMark` per Q7 → exactly ONE undo level removes group + bars; redo re-applies.
2. **Group edit/regenerate (headless):** `updatePlacementGroup` (new spacing / cover / Ø / edge distances / orientation) → the group's bars are re-generated to the NEW rule exactly (old bars gone, new bars rule-exact) → ONE undo level restores the pre-edit group AND its previous bars exactly (exact-reference restore, the M1 pattern).
3. **Host-follow + detach (headless):** `moveElement` on the host → the group's bars follow (§E revised 2026-08-09) and a post-move re-generation still satisfies the rule against the moved face (Q3 host-local params make this free); `moveBar` on a group member detaches it from the group (Q6 — §F.1 "moving individual bars breaks them from the group") → group rule and detached bar both survive correctly, ONE undo level restores membership + position.
4. **Collision probe (headless):** a group placed over pre-existing individual bars (and/or a second overlapping group) → the collision engine flags exactly the clashing bar pairs (centerline distance < r₁ + r₂); placement stays **non-blocking** (§K.4 — violations are warnings) and the clash report is exact (pair ids + distances).
5. **Placement UX (manual/author):** the Place Bar Group tool (G) over a real wall traced from a DXF background (the M2 workflow): capture face → define region → live translucent preview → params → commit; double-click a group bar selects the group (§B.5) and edits its params in the Properties panel; the individual Place Bar tool (B) is unchanged (fire-and-forget).

### 2. Engine math — face-local region sampling + spacing generation (Q1/Q3)

- Rust/WASM per §D.2 ("face sampling, spacing math" → Rust): `generate_bar_group_layout(face frame + region + {cover, Ø, spacing, edges, orientation}) → flat f64 path array + count` — pure arithmetic (positions = edge + k·spacing, endpoints inset by cover semantics, inward offset = cover + radius); cargo tests for the analytic corpus (horizontal/vertical, both orientations, edge-exact fits, spacing larger than region → single-bar/zero-bar behavior decided in-task and recorded).
